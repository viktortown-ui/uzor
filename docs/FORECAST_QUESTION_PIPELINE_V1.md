# Экспериментальный раздел «Будущее»: pipeline v1

«Будущее» проверяет, могут ли жители находить полезные городские темы, а редакция — превращать их в точные, ограниченные сроком и проверяемые вопросы. Эксперимент не является официальным прогнозом города, обещанием, муниципальным решением, опросом, рынком предсказаний или системой репутации.

## Три разных действия

1. **Предложение** — автор предлагает тему обычными словами; она приватна до решения редактора.
2. **Общественное рассмотрение** — жители отвечают, стоит ли редакции готовить тему. Голос не отвечает на вопрос о будущем и служит только рекомендательным сигналом.
3. **Экспериментальный прогноз** — отдельный формализованный исход, срок, источник проверки и личная вероятность.

Статусы: `submitted → in_review → needs_clarification/public_review/rejected/archived`; `needs_clarification → in_review/rejected/archived`; `public_review → selected/in_review/archived`; `selected → in_review/archived`. Только allowlist-редактор принимает решения. Ни количество голосов, ни статус `selected` не публикуют событие автоматически.

## Данные и безопасность

Автор видит свой исходный текст, варианты и публичное решение. Публичный RPC отдаёт только редакционный заголовок, описание, необязательную локацию/Delta, статус и агрегаты голосов — без UUID автора/редактора и предложенных вариантов. Редактор видит технический UUID автора, но не email. На всех таблицах включён RLS, прямые права `anon`/`authenticated` отозваны; доступ выполняют узкие `security definer` RPC с защищённым `search_path`. Авторитетные даты задаёт PostgreSQL.

Порядок применения: миграции 007, 008, 009, 010, затем 011. Первый редактор добавляется владельцем базы:

```sql
insert into public.forecast_question_editors (
  user_id,
  created_by,
  note
)
values (
  '<EDITOR_AUTH_USER_UUID>',
  '<EDITOR_AUTH_USER_UUID>',
  'Первый редактор экспериментального раздела Будущее'
);
```

## Границы v1

Выбранное предложение ещё не становится `forecast_event`: конвертация намеренно отсутствует, а `converted_event_id` остаётся `null`. Также исключены комментарии, уведомления, профили, рейтинги, автоматическая модерация, AI-генерация и редактор формальных исходов. Один приватный Brier score оценивает только один прогноз и не определяет общую точность или репутацию.

Следующий этап — **Question Studio** и версионированная конвертация выбранного предложения в экспериментальный `forecast_event` с формальными вариантами, сроком и источником проверки.

### Повторное общественное рассмотрение

В v1 возврат темы из `public_review` в `in_review` удаляет все голоса и очищает время начала рассмотрения. После изменения публичной формулировки редактор открывает новый раунд с новым серверным временем и нулевыми счётчиками. Это намеренно разрушительное правило не позволяет приписать старые голоса новому тексту.

Связь с Дельтой поддерживается серверным контрактом, но пользовательский выбор Дельты отложен до безопасного понятного picker-интерфейса; форма v1 не показывает поле UUID.
